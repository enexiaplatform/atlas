## Identity and authorization

Atlas maps the configured GoTrue origin and verified UUID to an Atlas person. It uses opaque, hashed, expiring sessions and service credentials. The membership lookup precedes SET LOCAL ROLE atlas_runtime and per-transaction workspace scope. Rotation invalidates a principal's keys and sessions. Revoking an upstream identity need not terminate an existing Atlas session immediately. Its lifetime is bounded by issuer expiry and eight hours. Decide the hosted revocation SLA before enabling sign-in.

Memoire verifies getUser against its own configured Supabase project, resolves a named personal workspace with the login client, then asks PostgreSQL for the active data owner using the native workspace header. The receiver requires an exact mapping of issuer, subject, native workspace, owner, Atlas organization, workspace, principal and allowed operations. It checks /api/me on every request. A separate high-entropy server capability restricts progress writes in the Memoire database. Review the receiver migration, polling instructions and permission names in Memoire docs/architecture/atlas-m03.md.

HELM's supabase/functions/helm-authority/index.ts validates the caller with its configured Supabase getUser, passes the verified user ID to the authority kernel and uses the HELM service role for authorized decisions. No shared issuer, membership directory or cross-product token revocation authority has been established. SSO federation requires an owner decision. HELM, Sentinel, Forge and Flow integration changes are NOT APPLICABLE.

## Staging activation and rollback

1. Select a dedicated isolated cluster and database per product, separate migration and runtime logins, a dedicated issuer project and private secret namespace. No real tenant records. Review [provisioning](operations.md) and copy [staging configuration](staging.env.example) into the approved secret manager. Keep originals in private Atlas bytea under the existing quota while measuring restore time and growth. Never expose the schema through the Memoire Data API.
2. With approval, snapshot both stores, apply Atlas migrations 001–004 and the Memoire native workspace, receipt and progress migrations in dependency order. Configure the Memoire PostgREST pre-request hook. Provision an Atlas consumer for exactly one workspace and a separate person for publication. Set the private progress-key digest in Memoire. Run negative scope checks with two synthetic tenants. Long-lived database and consumer credentials remain server-only.
3. The Atlas Vercel manifest retains Git deployments disabled. The hosted handler enforces text-only. With ATLAS_ENVIRONMENT=staging, initialization validates the named database, TLS mode, issuer origin and restricted gateway. Monitor /api/health/live and /api/health/ready plus receiver diagnostics and failed scheduler ticks. The readiness probe checks the database and runtime role. Monitor issuer and receiver reachability separately. Suppress request bodies, headers, connection strings and asset text from logs.
4. Set ATLAS_TRUSTED_PROXY_IP only for an exclusive immediate peer that overwrites X-Forwarded-For with one validated socket address. Restrict origin access at the network edge. Default throttling uses the socket. If the host cannot provide a stable authenticated ingress, use platform ingress limiting before enabling hosted login and validate observed behavior. Verify proxy body cap, base64 overhead and quota under load. The scanner contract is private and in-memory. Production needs a bounded private quarantine, scan timeout, approved engine/definitions and retention, then immutable promotion. No hosted binary switch exists.
5. Pause both writers and polling for a coordinated snapshot. The native drill copies a stopped same-version cluster. The embedded driver sends SIGINT on Linux and terminates the process tree on Windows. The Windows restart can require PostgreSQL crash recovery. Managed backup, PITR, encryption, geographic copies, RPO and RTO require target-environment evidence. Restore into fresh targets, compare bytes/digests, evidence attachment IDs, revisions, memberships, event sequences, receipts and cursor, confirm tenant isolation, then switch only by approval. Keep prior stores and credentials available for rollback. Revert to matching application/schema versions. Revoke progress capability and pause polling if rolling the receiver back, and restore previous RPC grants only with the matching version and explicit approval.
